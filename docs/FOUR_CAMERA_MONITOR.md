# 四路统一监看台

在 DGX 项目目录运行 `./run_multi.sh --config nodes.local.json`，或点击桌面的“RK3588 四路监看台”。配置文件要求恰好四台节点，编号、地址和裁判端口不重复。沿用 `nodes.example.json` 的格式、SSH 别名和环境要求，不增加节点侧依赖。

## 操作

- 默认四宫格，点击画面或顶栏 RK1–RK4，在同一窗口放大。Esc 或“四宫格”返回，四路的播放位置、暂停和速度各自保留。
- “全部开始录制”使用各节点原先保存的归档目录，分别后台启动；已经录制的节点继续录制。在大画面里可单独开始、停止、归档录像。
- 各小画面下方“最近 10 秒／30 秒”从该节点的 9100 环形缓存获取最新片段，不必等磁盘分段封存。加载期间继续直播，完成后该路进入回放。其他路不切换。
- 大画面的“回放”使用当前整场录像；时间轴从场次起点覆盖完整录制过程。刚看过最近片段时，点“回放”即可切回整场。
- 支持暂停、0.5×／0.25×、逐帧、标记、截图和原有录像库。键盘：空格播放/暂停，左右键逐帧，F1 直播，F2 整场回放。详情中的其他快捷键沿用单路界面。
- 单台离线时标出连接异常，其他三台继续。关闭窗口只断开显示连接，设备录像继续；停止录制仍在对应大画面内操作并确认。

## 实现与资源

每台相机只有一个 `StudioController`、一个 `LiveFeed`。四宫格和大画面复用同一个控制器，切换不重新连接。DGX 使用现有 NVDEC 解码主码流，并在本机缩放；RK3588 继续只编码一路 2448×2048 HEVC，不生成额外缩略码流。四宫格显示目标约 20 次刷新/秒，采集录像目标仍约 59.2 fps；界面 fps 标识为接收帧率。

统一窗口的回放也使用 DGX 的 GStreamer/NVDEC，先将 NV12 缩放到显示宽度，再转 BGR，避免四路都在 CPU 解码和缩放 5MP 画面。保留逐帧及精确跳转：按转封装写入的毫秒 PTS 做 `FLUSH | ACCURATE` seek，目标时间按同样规则取整。硬件路径不可用时记录日志并回退 OpenCV 软件解码，同时提示四路回放可能降速。原单路入口继续使用原来的解码工厂。

回放快照在后台拉取并转封装，主线程只接收完成事件。每台保留最近四份快照和可能正在看的较早快照，只清理自己 `ring-cache/recent_*` 下的临时目录，不清理原始录像。点击直播会取消尚未完成的快照切换，下载失败清理半截文件。

数据沿用 `~/.local/share/roller-derby-replay/<node>/`，快照单独存于 `<node>/ring-cache/`。归档目录沿用 `~/录像_rk/<node>/` 或节点已保存设置。统一窗口持有与单路启动器相同的四把 `monitor.lock`，同一个节点不能同时被单路与四路窗口占用。

统一窗口日志：`~/.local/share/roller-derby-replay/multi-monitor.log` 和 `multi-monitor-stdout.log`；每 10 秒写入 `multi-health.json`，记录每路帧计数、接收帧率、在线状态和回放位置。平板服务继续分别用 8611–8614，不把四路混成同一个服务。

## 现场注意

四路主码流合计约 120 Mbps；回放下载和归档还会产生突发流量。千兆有线网络应作为部署条件。现场 RK1 链路曾协商为 100 Mbps，30 秒快照约 113 MB，加载会比千兆节点慢；界面会显示进度。

节点启动前执行部署规范中的运行时性能配置。`deploy/bootstrap.sh node` 会记录之前的 USB 内存、CPU governor 值，再配置 `performance`；这些是运行时配置，设备重启后需要重新应用。2026-11-21 的四路验收发现 RK2、RK3 回到 `interactive` 时采集约 37 fps，补齐该配置后最近采集恢复约 59.2 fps，原先已丢的帧无法补回。

本功能不会解决原有 USB 控制器的长期稳定性问题，也不提供四台相机硬件同步触发。短时四路验收不能代替一小时以上的持续录制验收。

## 验证

```bash
/usr/bin/python3 -m unittest discover -s tests -v
/usr/bin/python3 -m py_compile multi_monitor.py studio_ui_rk.py
```

自动测试覆盖快照协议、截断/异常响应清理、转封装帧数不符、返回直播取消加载，以及四路共用主循环时不能提前推进其他相机的播放时钟。真实设备验收另检查四路并发直播、切换详情、最近回放、整场回放和断开其中一路显示连接时的隔离。

## 2026-11-21 实测结果

- rk1：1× 实际 3.712 秒内前进 3.726 秒；最终接收 59.29 fps。
- rk2：1× 实际 3.712 秒内前进 3.726 秒；最终接收 59.19 fps。
- rk3：1× 实际 3.712 秒内前进 3.714 秒；最终接收 59.39 fps。
- rk4：1× 实际 3.712 秒内前进 3.710 秒；最终接收 59.31 fps。

15 项自动回归通过，四路真实相机的独立暂停、0.25×、跨片段和逐帧通过。第四路主动关闭显示接收约 5 秒时，其他三路继续，重新启用后恢复。归档弹窗期间回放仍继续。

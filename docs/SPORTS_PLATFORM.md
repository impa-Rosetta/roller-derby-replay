# RK3588 体育赛事回放平台

DGX 桌面双击 **RK3588 体育赛事回放平台**。原 **RK3588 四路监看台** 快捷方式同样启动新版。命令行：`./run_multi.sh --config nodes.local.json`。

## 布局

左侧四画面整体按原始2448×2048比例紧密排列，不拉伸、不裁切源视频。单击选择相机，双击同窗放大，Esc 返回。右侧集中赛事、录制、回放、相机状态、事件标记和单路工具。底部四条录像轨共用刻度及一个播放指针。窗口缩小时右侧操作栏可滚动，底部时间轴保留。

录像及传输仍是原分辨率单路 HEVC；DGX NVDEC 解码并缩放显示，节点不新增缩略编码。

## 蓝白卡片界面（2026-11-21）

按用户给定参考图改为浅蓝底、白色圆角卡片、轻阴影、矢量图标和蓝色主按钮，视频区域保持深色。赛事录制、多机位回放、所选机位、时间校准、机位状态及赛事事件分别成卡片，时间轴沿用四轨共同指针。

小窗口会收紧机位状态卡，事件输入及标记按钮自动换行；控制栏可通过滚动条或直接在卡片上滚轮访问。已在2478像素宽屏及1200×800下截图核验，四路放大尺寸回归保持通过。使用独立sports_theme.py，不改变原单路界面配色；原生Tk矢量控件不新增安装依赖。

## 推荐操作流程

1. 点 **全部开始录像**。已有录像的设备不会重复启动。查看每台状态及成功数量，不以按钮点击代替启动成功。
2. 默认勾选 **四路联动**。直播期间可点 **最近10秒／30秒**，后台同时获取四路环形快照，不等待磁盘分段收尾；加载结束后共同回放，完整赛事轴保留。点 **返回直播** 不停止录像。
3. 拖动底部进度条，松开后四路共同定位。加载期间明确提示；可用画面准备好再一起播放。某一路没有该时刻的录像或加载失败，会明确标出，不借用末段画面冒充目标时间。
4. 共用播放/暂停、0.25×、0.5×、1×、2×和逐帧。空格播放/暂停，左右键逐帧。临时取消“四路联动”可检查选中相机，重新勾选后恢复共同定位。
5. **全部停止**只确认一次，再并发发送优雅停止，等节点完成文件收尾。录像保留，停止后仍可用整场时间轴回放，不弹出四个归档窗口。
6. 归档在选中相机的 **归档选中**里单独操作。默认不删除节点原文件；原有归档校验流程保留。关闭平台不会停止设备录像。

## 时间轴与赛事

轨道默认覆盖整场，录制越长自动扩展，不丢掉早期录像。绿色代表可读录像区间，空白代表缺少录像；红色为共同指针，事件为黄色标记。底部＋/−或滚轮缩放，Shift+滚轮平移，**全程**恢复完整范围。

赛事清单明确绑定四个录像目录，保存在 `~/.local/share/roller-derby-replay/matches/`，不把每台“最新文件夹”拼起来冒充同一场。组合识别优先完整长场次，可从下拉选择；**组合录像**允许逐台指定文件夹。2026-11-21 的四份一小时录像均保留，第2台之后额外的约6秒录像不再覆盖整场选择。

输入备注后点 **＋标记**，保存共同回放位置。双击事件可四路定位；支持删除和导出 JSON。校准值及标记随赛事清单持久保存，原视频不改写。

## 时间对齐的含义

共同进度条控制的是同一个赛事时刻，而不是四台相机各自“从零开始的第几秒”。每个分段用自己的拍摄时间锚点映射到赛事轴，缺口不伪装成连续画面。

新赛事自动通过有线SSH长连接，在握手完成后交换时间采样，估计每台相对DGX的时钟偏差并保存；录制中约每60秒更新采样，按时间插值补偿漂移。不会修改操作系统时间，也不需要安装新NTP服务。UI显示的往返误差仅指时钟采样估计，不等于相机曝光或画面同步精度。**这是软件时间对齐，不是硬件同步触发。**

旧录像没有当时的时钟校准，明确显示“旧录像尚未完成画面对齐”。可暂停四路于一个共同动作，取消联动后在选中一路找到同一动作，再点 **时间对齐 → 将该路当前帧对齐到共同指针**；也可按帧微调或输入秒数。参考指针保留为取消联动前的位置。重新勾选联动检查，并逐路校准。校准会保存，不重编码录像。

## 载入和跨段

一个单调时钟驱动所有回放画面。定位及下一段的NVDEC准备在后台完成，最新定位请求替代旧请求。下一段提前下载、转封装并建立解码器；临近分段末尾的随机跳转会先预缓冲下一段，再开始共同播放。正常跨段直接切换预备解码器；网络不足或片段不可用时显示缓冲/缺失状态。

现场 RK1 链路曾协商为100Mbps，所以首次跳到未缓存位置、拉取30秒快照可能需要数秒到十余秒；读取已缓存片段会更快。软件回放不改变节点本地录像。

## 部署与排查

沿用 `nodes.local.json` 的四个节点、独立缓存及8611–8614裁判端口。依赖与原版相同：系统Python、Tk、OpenCV、PyAV、GStreamer/GstApp及NVDEC。节点采集/编码环境、CPU performance及USB内存配置见 `DEPLOYMENT.md`，重启后运行时性能配置仍需重新应用。

日志：`~/.local/share/roller-derby-replay/multi-monitor.log`、`multi-monitor-stdout.log`。`multi-health.json`每5秒记录平台模式、共同位置、每路实际来源、录制/连接状态。每次新录制之前，会尽量把上一份 `/tmp/hk_record.log` 保存到对应节点上一个场次的 `record-runtime.log`。

## 验收

`/usr/bin/python3 -m unittest discover -s tests -v`。

本次以四份64–65分钟真实录像检查开头、中间、末尾、分段边界、共同暂停/慢放/逐帧、快速连续定位；又实际统一启动和停止四台节点，并验证录制中四路环形即时回看、停止后完整回放及原一小时录像仍可载入。另有回归覆盖时间偏差/漂移、缺口、坏路隔离、后台预载和旧定位解码器的资源释放。

已有一小时实录是本机配置的运行证据；本次界面改造不宣称根治过去出现过的USB控制器异常，也不把软件校准宣传为逐帧硬件同步。
